# 眠记网页版隔离与可靠性加固设计

日期：2026-09-03

## 目标

眠记当前只交付网页版/PWA。保留已有 Capacitor、Android、iOS、SQLite 和 Android 小组件源码，暂不删除，也不继续开发；网页版入口、运行过程和生产构建不得加载这些原生模块。

同时修正网页版导出备份、反馈隐私说明和版本描述，使界面展示与实际能力一致。

网页版采用三层数据保护：IndexedDB 保存日常记录；浏览器支持时允许用户主动申请“防自动清理保护”；所有环境保留定期外部 JSON 备份。该组合降低丢失概率，但不承诺永久保存。

## 范围

### 本次包含

- 网页入口直接创建 `IndexedDbSleepRepository`，不再导入或调用原生仓库工厂。
- 网页应用不再导入、执行或打包小组件桥接代码。
- 原生源码、工程目录和依赖保留，方便未来重新评估时恢复开发。
- 加固 JSON/CSV 浏览器下载流程并提供失败反馈。
- 仅在成功触发 JSON 导出后记录最近导出时间。
- 检查并展示浏览器真实的持久化状态；仅由用户点击申请保护，不在启动时自动申请。
- 将持久化能力称为“防自动清理保护”，明确它不能防止主动清除网站数据、卸载浏览器、换机或设备损坏。
- 明确说明反馈网络请求只发送用户主动填写的反馈正文和联系方式，不上传睡眠记录。
- 网页界面只使用 PWA、浏览器和 IndexedDB 相关描述。
- 增加自动化回归测试，并检查生产产物不含原生模块特征。

### 本次不包含

- 不构建、发布或测试 APK、IPA、App Store、应用商店或原生签名。
- 不修复 SQLite、原生事务、原生导出或 Android 小组件问题。
- 不删除 `android/`、`ios/`、Capacitor 配置、SQLite 实现及其测试。
- 不增加账号、云端睡眠数据库或自动上传睡眠记录。

## 方案

### 1. 网页运行链路

`main.tsx` 直接实例化 IndexedDB 仓库并渲染应用。`App.tsx` 不引用 `widget-bridge.ts`，也不发布小组件状态。由于 Vite 从入口建立依赖图，未被网页入口引用的原生实现不会进入 PWA 生产资源。

原生工厂和桥接文件继续留在源码中，但成为休眠模块。未来恢复 APP 开发时，应使用单独原生入口或构建模式重新接入，而不是让一个入口在运行时选择平台。

### 2. 浏览器导出

下载工具负责创建 Blob 地址、把临时链接加入文档、触发下载、移除链接，并在稍后释放 Blob 地址，避免部分移动浏览器因链接未挂载或地址过早释放而不下载。

下载工具若无法完成触发则抛出错误。JSON 导出由统一错误处理包装；只有触发成功后才更新 `lastManualExportAt`。界面将该时间描述为“最近执行导出”，不承诺用户一定把文件长期保存到了安全位置。

CSV 使用 `text/csv;charset=utf-8`，JSON 使用 `application/json;charset=utf-8`。

### 3. 防自动清理保护

设置页加载时调用 `navigator.storage.persisted()` 读取浏览器当前真实状态。支持该能力且尚未获得保护时，用户可以通过按钮主动调用 `navigator.storage.persist()`；页面根据返回值显示“已获得防自动清理保护”或“浏览器未授予保护”。

此状态只表示浏览器在空间紧张时不应自动驱逐该网站数据。界面同时说明：用户主动清除网站数据、卸载浏览器、换机或设备损坏仍会造成数据丢失，因此 JSON 外部备份仍是恢复依据。API 不支持或调用失败时不得显示已保护。

### 4. 反馈与隐私

反馈模块继续使用现有第三方表单服务，但在反馈区域旁明确说明：仅当用户点击提交时，反馈正文、可选联系方式和提交时间会发送给第三方邮件转发服务；睡眠记录不会附带或上传。

项目隐私文档和 README 不再使用容易被理解为“完全无网络请求”的绝对描述，而改为“睡眠记录不上传；反馈仅在用户主动提交时联网”。

### 5. 错误处理

- JSON 导出失败：保留原导出时间，显示可关闭且自动消失的错误提示。
- CSV 导出失败：显示相同类型的错误提示。
- 持久化状态检查失败：显示“无法确认”，不推断为已保护。
- 持久化申请被拒绝：说明由浏览器决定，并继续建议 JSON 备份。
- 反馈发送失败或超时：继续保留复制邮箱和系统邮件入口。
- IndexedDB 加载或写入失败：沿用现有加载失败页和顶部错误横幅。

## 测试与验收

所有行为修改遵循测试先行：先增加失败测试，再写最小实现。

验收条件：

1. 网页入口不导入 `repository-factory`，应用不导入 `widget-bridge`。
2. 生产资源中不出现 `CapacitorSQLite`、`SleepWidgetBridge` 或原生数据库名称。
3. JSON 下载成功触发后才更新最近导出时间；失败时不更新时间并显示错误。
4. 临时下载链接会加入并移出文档，Blob 地址延迟释放。
5. 刷新页面后重新读取浏览器持久化状态，不依赖旧的 React 内存状态。
6. 未获保护、拒绝、API 不支持和状态检查失败均不会显示“永久”或“已安全备份”。
7. 页面和文档准确说明反馈联网边界，明确睡眠记录不随反馈上传。
8. 现有单元、组件和移动端端到端流程全部通过。
9. 生产构建成功，PWA 离线资源正常生成。

## 数据与兼容性

本次不修改 IndexedDB 名称、对象仓库、备份 JSON 格式或睡眠记录模型，因此现有网页版记录与备份保持兼容。网页更新不得清除 IndexedDB。

保留的原生代码不参与本次网页版质量结论；未来重新启用前必须单独修复并完成真机验证。
